# 制药企业洁净区与批生产记录管理平台

面向洁净区环境监测、批生产记录编录、物料放行、偏差与变更控制、灭菌与清洁验证、成品检验与年度质量回顾的一体化药品生产质量管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pharma-cleanroom:entries` 这一项，或调用 `resetModule(模块)`。

## 留样管理专项规则

留样台账要同时下发库房与车间两处，业务规则集中在 `src/api/retain-service.ts` 与
`src/data/retain-catalog.ts`，页面只做渲染与表单收集：

- **按留样期限分册导出**：点「按留样期限分册导出」立即下载一个 zip（内置最小 STORE 打包实现，
  无第三方依赖），每册只写留样编号、留样数量、存放条件、对应批号，册名即留样期限；某期限无留样
  时该册落一页「分册说明」而不是留空，另附 `00-下发说明.csv`，不交空壳包。
- **销毁核准**：状态链为 待留样 → 已留样 → 已到期 → 待销毁 → 已销毁；申请销毁必须有经手人签字，
  质量部核准销毁必须有质量部签字，缺签字一律拒收。
- **状态逐级流转**：`retainsample` 元数据开了 `strictFlow`，跨级动作（如已留样直接销毁）拒收。
- **重复导出只计一次**：导出留痕存在 `pharma-cleanroom:retain-exports`，同一份留样重复导出只计
  入重复数，「已下发留样数」按去重统计，页面可查看导出留痕。
- **稳定性考察待办**：已到期、待销毁的留样自动反映为稳定性考察页顶部的联动待办。
- **存放条件同一套**：常温/阴凉/冷藏/冷冻统一目录（含温湿度区间），登记、导出共用；目录外条件、
  温度越界、湿度超限在登记时挡回。
- **数量/期限冲突按优先级**：同一留样编号在留样数量或留样期限上撞车时，按登记入口优先级
  （质量部 ＞ 库房 ＞ 车间）取高的一版，平级时后登记覆盖，低优先级版本被挡回。
